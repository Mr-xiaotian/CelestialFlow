# src/celestialflow/benchmark/util_benchmark.py

> 📅 Last Updated: 2026/10/30

`benchmark/util_benchmark.py` provides performance benchmarking functionality for executors and task graphs, used to compare performance differences across execution modes.

> ⚠️ This file defines internal benchmark utility functions, not public API; `benchmark_executor` and `benchmark_graph` become the supported public API only after being exported through `celestialflow/__init__.py`.

## Design Purpose

In real projects, choosing the right execution mode is critical for performance. The benchmarking tool can:
- Compare elapsed time across different execution modes
- Validate parallelization effects
- Discover performance bottlenecks

## Main Functions

### benchmark_executor

Benchmarks a `TaskExecutor`.

```python
async def benchmark_executor(
    sync_executor: TaskExecutor[Any, Any],
    async_executor: TaskExecutor[Any, Any],
    task_source: Iterable[Any],
    execution_modes: list[str] | None = None,
) -> dict[str, Any]:
    """
    Benchmarks an executor.

    :param sync_executor: Sync executor template (for serial/thread execution_mode)
    :param async_executor: Async executor template (for async execution_mode)
    :param task_source: Task source, used to generate the task list
    :param execution_modes: List of execution modes, default ["serial", "thread", "async"]
    :return: Test result dict (contains use_time, execution_modes, table)
    """
```

Test flow:
1. `task_source` is first fully materialized into `task_list` (`list(task_source)`), so that all subsequent modes run the same batch of tasks
2. Iterate over `execution_modes` one by one; `async` mode clones `async_executor`, while the other modes clone `sync_executor`, to avoid state contamination
3. Call `set_execution_mode(mode)` to set the current test mode
4. Take the start point `start_perf` with `time.perf_counter()`; then `serial`/`thread` modes call `run(task_list)` (internally completing task injection, termination signal injection, and startup), while `async` mode calls `await run_async(task_list)`; the difference `time.perf_counter() - start_perf` is recorded as that mode's elapsed time
5. Output the time table via `format_table(use_time, execution_modes, ["Time"])` and `print` it; return the result dict

> The timing window wraps the entire `run()` / `run_async()` call, so it **includes the setup and teardown of runtime resources (`lifecycle` / `log` spouts, observers)**, rather than pure task execution time.

Sample output (a bordered table generated by `format_table`, values in seconds; the row-name column is `#` and the data column is `Time`):
```
+--------+--------+
| #      | Time   |
+--------+--------+
| serial | 2.3401 |
| thread | 0.8932 |
| async  | 0.6714 |
+--------+--------+
```

### benchmark_graph

Benchmarks a `TaskGraph`.

```python
async def benchmark_graph(
    sync_graph: TaskGraph,
    async_graph: TaskGraph,
    init_tasks_dict: Mapping[str, Iterable[Any]],
    graph_modes: list[str] | None = None,
    execution_modes: list[str] | None = None,
) -> dict[str, Any]:
    """
    Benchmarks a task graph, covering all combinations of ``graph_mode × execution_mode``.

    - ``sync_graph`` is used for cells where ``execution_mode in {"serial", "thread"}``;
    - ``async_graph`` is used for cells where ``execution_mode == "async"``;
    - ``graph_mode`` determines whether the current cell is started with ``run()`` or ``run_async()``.

    :param sync_graph: Sync task graph template (for serial/thread execution_mode)
    :param async_graph: Async task graph template (for async execution_mode)
    :param init_tasks_dict: Initial task dictionary, with task label as key and task list as value
    :param graph_modes: List of graph execution modes, default ["serial", "thread", "async"]
    :param execution_modes: List of execution modes, default ["serial", "thread", "async"]
    :return: Test result dict (contains use_time, table, graph_modes, execution_modes)
    """
```

Test flow:
1. `init_tasks_dict` is first shallow-copied into `base_tasks` (each node's tasks are then materialized into a `list`), ensuring every cell starts from the original task set
2. Iterate over all combinations of `graph_modes` × `execution_modes`
3. Clone the task graph (clone `async_graph` when `execution_mode="async"`, otherwise clone `sync_graph`). `clone_graph` internally uses `isinstance` to check that all nodes are `TaskExecutor`; if specialized nodes such as `TaskSplitter` are present, it raises `ConfigurationError`
4. Call `set_graph_mode(graph_mode)` and `set_node_execution_mode(execution_mode)`, and make a fresh copy of the task dictionary for the current cell
5. Take the start point `start_perf` with `time.perf_counter()`: when `graph_mode="async"`, execute `await run_async()`; for other graph modes, execute `run()`, where combinations with `execution_mode="async"` are started via `asyncio.to_thread(cloned_graph.run, run_tasks)` to avoid conflict with `benchmark_graph()`'s own event loop
6. Record `time.perf_counter() - start_perf`, and output the time table via `format_table(test_table_list, graph_modes, execution_modes, "graph/execution")`, with the row-name column being `graph/execution`

> The timing window likewise wraps the entire `run()` / `run_async()` call, including runtime resource setup and teardown.

Sample output (values in seconds):
```
+-----------------+--------+--------+--------+
| graph/execution | serial | thread | async  |
+-----------------+--------+--------+--------+
| serial          | 5.2341 | 3.4512 | 3.2123 |
| thread          | 2.1234 | 1.8912 | 1.6543 |
| async           | 2.0534 | 1.7345 | 1.4234 |
+-----------------+--------+--------+--------+
```

## Usage Examples

### Testing an Executor

```python
import asyncio
from celestialflow import TaskExecutor
from celestialflow.benchmark.util_benchmark import benchmark_executor


# Define sync task
def sync_task(x):
    return x * 2


# Define async task
async def async_task(x):
    await asyncio.sleep(0.01)
    return x * 2


# Create executors
sync_executor = TaskExecutor("SyncBench", sync_task)
async_executor = TaskExecutor("AsyncBench", async_task)

# Run benchmark
asyncio.run(
    benchmark_executor(
        sync_executor=sync_executor,
        async_executor=async_executor,
        task_source=range(1000),
        execution_modes=["serial", "thread", "async"],
    )
)
```

### Testing a Task Graph

```python
import asyncio
from celestialflow import TaskGraph, TaskExecutor
from celestialflow.benchmark.util_benchmark import benchmark_graph


def process_a(x: int) -> int:
    return x * 2


def process_b(x: int) -> int:
    return x + 1


async def async_process_a(x: int) -> int:
    return x * 2


async def async_process_b(x: int) -> int:
    return x + 1


# Create sync nodes
stage_a = TaskExecutor("A", process_a)
stage_b = TaskExecutor("B", process_b)

# Create async nodes
async_stage_a = TaskExecutor("A", async_process_a)
async_stage_b = TaskExecutor("B", async_process_b)

# Build sync graph
sync_graph = TaskGraph(name="SyncGraph")
sync_graph.set_nodes(nodes=[stage_a, stage_b])
sync_graph.connect([stage_a], [stage_b])

# Build async graph
async_graph = TaskGraph(name="AsyncGraph")
async_graph.set_nodes(nodes=[async_stage_a, async_stage_b])
async_graph.connect([async_stage_a], [async_stage_b])

# Run benchmark (benchmark_graph is an async function, requires await)
asyncio.run(
    benchmark_graph(
        sync_graph=sync_graph,
        async_graph=async_graph,
        init_tasks_dict={stage_a.get_name(): range(100)},
    )
)
```

## Test Matrix

### Executor Test Dimensions

| Dimension | Description |
|-----------|-------------|
| `serial` | Single-threaded sequential execution |
| `thread` | Thread pool concurrent execution |
| `async` | Coroutine-based asynchronous execution |

### Task Graph Test Dimensions

**Graph Mode**:
- `serial`: Nodes run on the main thread
- `thread`: Nodes run in separate threads
- `async`: The graph is dispatched uniformly in the event loop; sync nodes are moved to threads, async nodes run directly as coroutines

**Execution Mode**:
- `serial`: Sequential execution within the node
- `thread`: Thread pool execution within the node
- `async`: Coroutine-based async execution within the node

Combination examples:
| Graph \ Execution | serial | thread | async |
|-------------------|--------|--------|-------|
| serial | S-S | S-T | S-A |
| thread | T-S | T-T | T-A |
| async  | A-S | A-T | A-A |

## Output Information

### Time Table

Displays the execution time for each configuration.

### Return Value

`benchmark_executor` returns a dict containing:
- `use_time`: `list[list[float]]`, one row per `execution_mode`, each row containing a single element (corresponding to the table's single `Time` column), with row order matching `execution_modes`
- `execution_modes`: List of tested execution modes (corresponding to the table's row names)
- `table`: Formatted time table string (column name is `["Time"]`, row-number column header is the default `#`)

`benchmark_graph` returns a dict containing:
- `use_time`: `list[list[float]]`, the elapsed-time matrix of `graph_modes × execution_modes` (rows and columns correspond to the table)
- `table`: Formatted time table string (row-name column is `graph/execution`)
- `graph_modes`: List of tested graph modes (corresponding to table rows)
- `execution_modes`: List of tested execution modes (corresponding to table columns)

## Notes

1. **Cloning mechanism**: Each test clones the original object to avoid state contamination
2. **Fixed tasks**: `benchmark_executor` materializes the task source first, and `benchmark_graph` re-copies the task list for each cell, ensuring each mode runs the same batch of tasks
3. **Resource contention**: Thread mode results may be affected by resource contention; multiple tests are recommended
4. **Async requirement**: Both `benchmark_executor` and `benchmark_graph` are async functions, requiring `await` or `asyncio.run`
5. **Template separation**: Both `benchmark_executor` and `benchmark_graph` require separate sync/async templates, since `execution_mode="async"` needs async functions
6. **Matrix completeness**: The current implementation of `benchmark_graph` defaults to covering all 9 combinations of `serial/thread/async × serial/thread/async`
7. **Node type limitation**: The internally used `clone_graph` only supports `TaskExecutor` nodes; if the graph contains specialized nodes such as `TaskSplitter` / `TaskRouter`, `ConfigurationError` is raised
8. **Invalid modes**: Passing a string other than `serial` / `thread` / `async` in `execution_modes` / `graph_modes` raises `InvalidOptionError` at `set_execution_mode()` / `set_graph_mode()`
9. **Timing scope**: Both functions use `time.perf_counter()`, and the timing window includes the runtime resource setup and teardown of `run()` / `run_async()`, so the values are somewhat large and are not equal to pure task execution time
10. **Configuration lost by cloning**: `clone_executor` only copies `name` / `func` / `execution_mode` / `max_workers` / `max_retries` / `max_info` and `retry_exceptions`; `max_queue_size`, `skip_func`, and already-registered observers all revert to defaults
11. **Internal tool**: `util_benchmark.py` itself is an internal benchmark module; external code should access it via `from celestialflow import benchmark_executor / benchmark_graph`
